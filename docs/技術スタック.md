# 技術スタック

[← 要件定義に戻る](../要件定義.md)

今後の実装・設計・ディレクトリ構成・ライブラリ選定は、原則としてこの技術スタックを前提に進める。

## フロントエンド

| 分類 | 内容 |
|---|---|
| ライブラリ | React |
| ビルドツール | Vite |
| ドラッグ&ドロップ | dnd-kit（`@dnd-kit/core` / `@dnd-kit/sortable` / `@dnd-kit/utilities`） |
| スタイリング | CSS Modules（`*.module.css`） |
| パッケージ管理 | npm |
| ディレクトリ | `frontend/` |

## バックエンド

| 分類 | 内容 |
|---|---|
| 言語 | Java 25（最新LTS） |
| フレームワーク | Spring Boot 4.1.0（最新安定版） |
| API形式 | REST API |
| データ保持 | バックエンドのインメモリ（DBは一旦使用しない方針。詳細は下記「データベース」参照） |
| パッケージ管理 | Gradle（Gradle Wrapper使用） |
| ディレクトリ | `backend/` |

Javaバージョンは `build.gradle` の Toolchain 指定（`JavaLanguageVersion.of(25)`）で固定する。ローカルに指定バージョンのJDKが無い環境でもビルドできるよう、`settings.gradle` に Foojay Toolchain Resolver プラグインを導入し、初回ビルド時にGradleが自動で対応するJDKを取得する構成にしている。

## データベース

現時点ではDBを使用しない方針（講義の進行に合わせた措置）。データはバックエンド（Spring Boot）のアプリケーション内メモリで保持し、`spring-boot-starter-data-jpa` やPostgreSQLドライバへの依存は持たない。

| 分類 | 内容 |
|---|---|
| 現状 | DBなし。バックエンドのインメモリ（`List`/`Map`等）でデータを保持する |
| 制約 | バックエンドプロセスを再起動するとデータは初期状態に戻る |
| 将来 | 講義の進行に合わせてPostgreSQL等の導入を検討（一度PostgreSQL接続の動作確認は実施済み） |

## 開発ツール

| ツール | 用途 |
|---|---|
| Git / GitHub | バージョン管理・ソースコードのホスティング |
| npm | フロントエンドのパッケージ管理・スクリプト実行 |
| Gradle（Wrapper） | バックエンドのビルド・依存管理・実行（`./gradlew bootRun` 等） |
| ブラウザ / IDEの開発者ツール | 動作確認・デバッグ |

## ディレクトリ構成

```
frontend/   … React + Vite製フロントエンド（npm管理）
backend/    … Spring Boot製バックエンド（Gradle管理）
docs/       … 要件定義の詳細ドキュメント
```

フロントエンドとバックエンドを同一リポジトリ内で管理するモノレポ構成とする。
