# 機能要件

[← 要件定義に戻る](../要件定義.md)

## 1. ボード・リスト

- ボードは **1つのみ** 管理できればよい（複数ボードの切り替えは不要）
- リストは自由に **追加・削除** できる（初期状態は「未着手」「作業中」「完了」の3つ）

## 2. カード

| 機能 | 内容 |
|---|---|
| カードの追加 | リストに新しいカードを作成できる |
| カードの削除 | 不要なカードを削除できる（削除前に確認あり） |
| カードの編集 | カードのタイトル・期限・優先度を後から編集できる |
| カードの移動 | カードをリスト間で移動できる（例: 未着手 → 作業中）。ドラッグ&ドロップ、またはカード上の移動先セレクトボックスのどちらでも操作できる |
| カードの並べ替え | 同一リスト内でカードをドラッグ&ドロップし、任意の位置に並べ替えられる（ドロップ先カードの上半分/下半分でカードの直前・直後に挿入） |
| 優先度順への一括並べ替え | リストごとに用意されたボタン操作で、そのリスト内のカードを優先度「高→中→低（未設定は末尾）」の順に一括で並べ替えられる。同じ優先度同士は元の順序を維持する |
| 期限の設定 | カードに締切日を設定し、表示できる（表示のみでよく、警告表示や自動並び替えは不要） |
| 優先度の設定 | 「高・中・低」の3段階で優先度を設定し、色分けして表示する |

## 3. データ永続化

- カードやリストの変更はフロントエンド（React）からバックエンド（Spring Boot）のREST APIを呼び出して行う
- データはバックエンドのインメモリ（アプリケーション内のオブジェクト）で保持する。DBは一旦使用しない方針（講義の進行に合わせて後日導入を検討）
- ブラウザをリロード・再訪した際は、バックエンドAPI経由で最新のデータを取得して表示する。ただしバックエンドプロセスを再起動すると、データは初期状態にリセットされる
